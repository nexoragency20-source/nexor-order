# NEXOR Orders — الرد الاجتماعي التلقائي وإنشاء الطلب بعد التأكيد

## ما الذي يفعله التدفق؟

1. يستقبل Backend رسائل Instagram أو Facebook Messenger عبر Meta Webhooks ويخزن الرسائل في `ConversationMessage`.
2. إذا كان الرد الآلي مفعلاً على اتصال القناة، ولم تكن المحادثة متوقفة يدوياً، يرسل Backend كتالوج المتجر النشط وسياقاً مختصراً ومنقحاً إلى Gemini.
3. يطابق Gemini طلب العميل مع معرّفات المنتجات الموجودة فعلياً في كتالوج المتجر. لا يُسمح له باختراع منتج أو سعر أو تنفيذ استعلام/كتابة في قاعدة البيانات.
4. يجمع Backend الاسم والهاتف والعنوان محلياً، ثم يعيد قراءة الأسعار والمخزون وسعر الصرف من قاعدة البيانات ويُرسل ملخصاً للزبون.
5. لا يُنشأ الطلب إلا عندما يرسل العميل رسالة مستقلة نصها `تأكيد الطلب` (مع السماح بالاختلافات الإملائية المحددة في الكود).
6. يُنشئ `OrdersService` العميل عند عدم وجوده بالهاتف، ويُنشئ طلباً عادياً بحالة `PENDING` وبنود `OrderItem` داخل معاملة واحدة. يُحفظ مرجع المحادثة ورسالة التأكيد لمنع تكرار الطلب عند إعادة إرسال Webhook.
7. بعد الإنشاء، يرسل NEXOR رقم الطلب والإجمالي إلى العميل. تبقى مراجعة الطلب واعتماده بيد موظفي المتجر.

## إعداد Gemini

أضف هذه المتغيرات إلى `backend/.env` مع الإبقاء على إعدادات قاعدة البيانات وJWT الحالية:

```env
GEMINI_API_KEY="مفتاح جديد صالح"
GEMINI_MODEL="gemini-3.1-flash-lite"
GEMINI_BASE_URL="https://generativelanguage.googleapis.com/v1beta"
```

المفتاح يبقى في Backend فقط، ولا يوضع في Flutter أو المتصفح. لا تستخدم مفتاحاً سبق كشفه أو مشاركته.

## إعداد Meta

أضف القيم التالية في `backend/.env`:

```env
META_APP_ID=""
META_APP_SECRET=""
META_REDIRECT_URI="https://YOUR_PUBLIC_API_DOMAIN/api/v1/conversations/oauth/callback"
META_WEBHOOK_VERIFY_TOKEN="قيمة عشوائية طويلة تختارها أنت"
META_TOKEN_ENCRYPTION_KEY="64 خانة hex تمثل 32 بايت"
```

لتوليد مفتاح تشفير عشوائي:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

يجب أن يطابق `META_REDIRECT_URI` عنوان Callback المسجل حرفياً في لوحة تطبيق Meta. استخدم نطاقاً عاماً عبر HTTPS؛ عنوان `localhost` لا يمكن لـ Meta الوصول إليه لإرسال Webhooks.

في لوحة Meta Developer:

- أضف منتجات Facebook Login / Messenger وInstagram Messaging بحسب نوع القناة المطلوب.
- اضبط OAuth Redirect URI على القيمة نفسها أعلاه.
- اضبط Webhooks على `https://YOUR_PUBLIC_API_DOMAIN/api/v1/conversations/webhook`.
- أدخل Verify Token نفسه الموجود في `META_WEBHOOK_VERIFY_TOKEN`.
- اشترك في أحداث الرسائل للقناة المناسبة، وامنح الصلاحيات المطلوبة مثل `pages_messaging` و`pages_manage_metadata` و`instagram_manage_messages` و`instagram_basic` وفق إعداد التطبيق ونوع الحساب.
- حساب Instagram يجب أن يكون احترافياً ومرتبطاً بصفحة Facebook مناسبة. وقد تتطلب الرسائل الواردة إلى أشخاص خارج أدوار التطبيق تفعيل وضع Live ومراجعة Meta لصلاحيات التطبيق.

## ترحيل قاعدة البيانات وتشغيل Backend

مهم: بعد استلام هذه النسخة يجب توليد Prisma Client من المخطط المحدّث قبل تشغيل الخدمة؛ ملفات العميل المولّدة الموجودة في أي نسخة أقدم لا تتضمن حقول الذكاء الاجتماعي الجديدة.

من مجلد `backend`:

```powershell
npm install
npm run db:generate
npm run db:deploy
npm run build
npm run start:dev
```

`db:deploy` يطبق Migration باسم `20261111195000_add_social_ai_order_flow`، ويضيف:

- `ChannelConnection.aiAutoReplyEnabled` — تشغيل الرد الآلي لكل حساب اجتماعي، وهو متوقف افتراضياً.
- `Conversation.aiPaused` و`Conversation.aiOrderDraft` — إيقاف مؤقت للمحادثة ومسودة جمع الطلب.
- `Order.sourceConversationId` و`Order.sourceConfirmationMessageId` — ربط الطلب بالمحادثة ومنع تكرار التسجيل.

تأكد من ضبط `DATABASE_URL` و`DIRECT_URL` وفق بيئتك قبل أوامر Prisma.

## تفعيل الرد الآلي من NEXOR

1. افتح صفحة **مركز المحادثات**.
2. اربط حساب Instagram أو Facebook من زر **ربط**. أكمل OAuth من Meta.
3. بعد عودة الحساب وظهوره ضمن الاتصالات، فعّل مفتاح الذكاء الاصطناعي بجانب الحساب المطلوب.
4. يبدأ الرد التلقائي فقط على الرسائل الجديدة الواردة بعد التفعيل. يبقى بإمكان الموظف إرسال رد يدوي؛ وعند الإرسال اليدوي يتوقف AI مؤقتاً لهذه المحادثة.
5. يمكن إيقاف AI أو استئنافه لكل محادثة من رمز المساعد أعلى نافذة المحادثة.

لا يعمل الإرسال الآلي خارج نافذة الرد المعتادة البالغة 24 ساعة من آخر رسالة واردة، التزاماً بقيود Meta. إذا طلب العميل موظفاً، يحوّل NEXOR المحادثة إلى متابعة بشرية بإيقاف AI لهذه المحادثة.

## قواعد إنشاء الطلب

- رسالة العميل التي تحتوي على المنتج لا تنشئ طلباً بمفردها.
- يجمع النظام الاسم ورقم الهاتف وعنوان التوصيل، ثم يعرض المنتجات والكميات والأسعار والإجمالي.
- عبارة `تأكيد الطلب` فقط هي التي تسمح بإنشاء الطلب.
- يعاد التحقق من السعر والكمية وسعر الصرف داخل مسار إنشاء الطلب. إذا تغير السعر أو المخزون أثناء التأكيد، لا ينشئ النظام طلباً بالسعر القديم ويطلب مراجعة الملخص.
- الطلب يُنشأ بحالة `PENDING`، ولا يخصم المخزون عند هذه المرحلة؛ الخصم يتبع دورة اعتماد الطلب الحالية داخل NEXOR.
- لا يُرسل الاسم أو الهاتف أو العنوان إلى Gemini؛ يجمع Backend هذه البيانات محلياً. أما نصوص الرسائل الأخرى وبيانات الكتالوج مثل أسماء المنتجات وأسعارها ومخزونها فيتم إرسالها إلى Gemini لمعالجة نية العميل ومطابقة المنتجات. راجع سياسة Google قبل استخدام بيانات تجارية حساسة.

## اختبار آمن قبل التشغيل الحقيقي

استخدم حساباً تجريبياً ومنتجات غير حساسة، وارسل رسالة من حساب مستخدم اختبار:

- اسأل عن منتج موجود بالكتالوج؛ يجب أن يرد NEXOR بمعلومات المنتج.
- اطلب منتجاً وحدد الكمية؛ يجب أن يجمع الاسم والهاتف والعنوان.
- تأكد من ظهور ملخص السعر والكمية قبل التسجيل.
- أرسل `تأكيد الطلب`؛ يجب أن يظهر طلب واحد بحالة `PENDING` في شاشة الطلبات، مع عميل مرتبط وبنود المنتجات.
- أعد إرسال نفس Webhook أو تحقق من عدم تكرار الطلب؛ مفتاح رسالة التأكيد يمنع التكرار.
- جرب `إلغاء الطلب` قبل التأكيد؛ يجب إلغاء المسودة فقط دون إنشاء طلب.

## حدود التشغيل الحالية

- معالجة الطوابير لكل محادثة داخل ذاكرة عملية Backend الواحدة؛ عند تشغيل عدة نسخ Backend أو الحاجة إلى ضمان إعادة محاولة الرسائل بعد تعطل العملية، يوصى لاحقاً بنقل المعالجة إلى طابور دائم مثل BullMQ/Redis أو جدول Jobs في PostgreSQL.
- يجب مراجعة حالة Meta App Review وقيود الصلاحيات ونافذة المراسلة قبل تفعيل القناة مع زبائن حقيقيين.
- الرد الآلي متوقف افتراضياً لكل اتصال جديد، ويجب تفعيله صراحةً من شاشة مركز المحادثات بعد اختبار الحساب.
