# ربط NEXOR AI ببيانات المتجر عبر Google Gemini

تم ربط وحدة NEXOR AI في NestJS بواجهة Gemini Developer API، كما أن شاشة Flutter تتصل بالخادم فقط. لا تضع مفتاح Gemini داخل تطبيق Flutter.

## 1) إعداد مفتاح Gemini

1. أنشئ مفتاحاً من [Google AI Studio](https://aistudio.google.com/api-keys).
2. افتح ملف `backend/.env` الموجود لديك. لا تستبدل إعدادات قاعدة البيانات الحالية؛ أضف أسطر Gemini التالية إليها فقط. إذا لم يكن الملف موجوداً، أنشئه اعتماداً على `.env.example`.
3. أضف الإعدادات التالية، وضع المفتاح محلياً على الخادم فقط:

```env
GEMINI_API_KEY="ضع_مفتاح_Gemini_هنا"
GEMINI_MODEL="gemini-3.1-flash-lite"
GEMINI_BASE_URL="https://generativelanguage.googleapis.com/v1beta"
```

4. أعد تشغيل Backend باستخدام `npm run start:dev` أثناء التطوير، أو نفّذ `npm run build` ثم `npm run start` للتشغيل المبني.
5. سجّل الدخول إلى NEXOR Orders وافتح صفحة **مساعد AI**؛ ستظهر حالة المحرك متصلاً مع اسم النموذج.

النموذج الافتراضي مضبوط على `gemini-3.1-flash-lite` لأنه النموذج الذي اجتاز اختبار توليد الإجابة من المشروع المرتبط بالمفتاح. يمكنك اختيار أي نموذج آخر يعرضه endpoint الخاص بقائمة النماذج ويدعم `generateContent`، مع مراعاة حدود الاستخدام المتاحة لمشروعك.

## 2) المسارات

- `GET /api/v1/ai/status` يعرض حالة الإعداد ومزود الخدمة والنموذج.
- `POST /api/v1/ai/chat` يرسل السؤال وسياق المتجر إلى Gemini.

كلا المسارين يتطلبان JWT صالحاً عبر `Authorization: Bearer <token>`.

مثال جسم طلب المحادثة:

```json
{
  "message": "ما المنتجات التي قاربت على النفاد؟",
  "history": [
    { "role": "user", "content": "حلل أداء المتجر" },
    { "role": "assistant", "content": "..." }
  ]
}
```

## 3) البيانات التي يقرأها المساعد

يُنشأ ملخص حي عند كل سؤال ويشمل:

- مبيعات وطلبات آخر 30 يوماً، والخصومات، والمرتجعات، وصافي المبيعات بعد المرتجعات.
- حالات الطلبات خلال الفترة.
- عدد المنتجات الفعالة وقائمة أول 20 منتجاً منخفض المخزون.
- أكثر 10 منتجات مبيعاً حسب قيمة بنود الطلب المسجلة، قبل خصم مستوى الفاتورة وأجور الشحن.
- عدد العملاء الفعالين دون إرسال أسماء أو بيانات تواصل.
- إجماليات فواتير الشراء المستلمة.
- الحركات المالية المجمعة حسب النوع والعملة.
- العملة الافتراضية وسعر الصرف الحالي.

كل استعلام بيانات مقيّد بـ `storeId` المأخوذ من JWT، مع إعادة التحقق من المستخدم والعضوية والمتجر. لا يقبل endpoint أي `storeId` من التطبيق.

## 4) الخصوصية والحدود

- لا تُرسل من قاعدة بيانات NEXOR أسماء العملاء أو الموردين أو الهواتف أو البريد أو العناوين أو الرسائل الواردة في قنوات التواصل. لكن نص السؤال وآخر رسائل المحادثة، إضافة إلى أسماء المنتجات والكميات والمؤشرات التجارية المجمعة، تُرسل إلى Google Gemini لمعالجة الطلب. لا تدخل بيانات شخصية أو كلمات مرور أو أسراراً تجارية لا ترغب بمشاركتها مع المزود.
- يستخدم الاتصال ترويسة `x-goog-api-key`، ولا يرسل المفتاح إلى Flutter أو المتصفح؛ يبقى في متغيرات Backend البيئية.
- المساعد للقراءة والتحليل والتوصيات فقط؛ لا ينفذ أوامر لتعديل الطلبات أو المخزون أو الحسابات.
- صافي المبيعات بعد المرتجعات ليس صافي الربح المحاسبي. كما تُعرض الحركات المالية منفصلة عن إجماليات المبيعات والمشتريات لتجنب جمع العملية نفسها مرتين.
- فترة الملخص ثابتة حالياً: آخر 30 يوماً، والقائمة المعروضة للمخزون المنخفض محدودة بأول 20 صنفاً.
- لا يتم حفظ سجل المحادثة في قاعدة بيانات NEXOR في هذه النسخة؛ تاريخ المحادثة موجود داخل واجهة المستخدم فقط.
- حدود المجاني والحصص تختلف حسب النموذج والمشروع وقد تتغير. أخطاء `429` تعني بلوغ حد الاستخدام/الطلبات، وأخطاء `503` تعني أن النموذج غير متاح مؤقتاً.

## 5) التحقق

بعد إعداد المفتاح وتشغيل الخادم، افتح شاشة المساعد أو استدعِ `GET /api/v1/ai/status` بعد تسجيل الدخول. أرسل سؤالاً بسيطاً من Flutter، ثم راجع السجل في Backend عند الحاجة. لا تشارك ملف `.env` أو مفتاح API عند طلب الدعم.
