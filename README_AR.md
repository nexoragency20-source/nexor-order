# NEXOR — لوحة المالك ونظام أكواد التفعيل والاشتراكات

هذه الحزمة مبنية على الملفات التي أرسلها المستخدم من مشروع `nexor_orders`. وهي حزمة تحديث تضاف فوق المشروع الحالي، وليست مشروعاً مستقلاً.

## ما الذي أضيف؟

- لوحة دخول مستقلة لمالك NEXOR بصلاحية `PlatformAdmin` منفصلة عن حسابات المحلات.
- إنشاء محل من لوحة المالك وربطه بمؤسسة ومتجر مستقلين في قاعدة البيانات.
- إصدار كود تسجيل فريد للمحل، مع اختيار شهري أو 3 أشهر أو 6 أشهر أو سنوي أو مدة مخصصة.
- يبدأ عدّ الاشتراك عند استخدام صاحب المحل للكود لأول مرة، وليس عند إصدار الكود.
- كود الاستخدام الأول لمرة واحدة فقط. يُخزّن Hash للكود ولا يُخزّن الكود الصريح في قاعدة البيانات، ويظهر الكود الكامل مرة واحدة بعد إنشائه.
- تسجيل صاحب المحل كـ `OWNER` داخل مؤسسة المحل الذي يطابق الكود فقط. لا يستطيع اختيار محل آخر من واجهة التسجيل.
- تجديد اشتراك المحل من لوحة المالك. يبدأ التجديد من نهاية الاشتراك الحالي إن كان ما زال فعالاً، وإلا يبدأ من وقت التجديد؛ لتجنّب تداخل الفترات.
- إيقاف محل وإعادة تفعيله يدوياً من لوحة المالك.
- عرض المحلات القديمة الموجودة قبل نظام الاشتراك بحالة مستقلة، مع إمكانية إدخال كل محل في نظام الاشتراكات يدوياً من لوحة المالك دون حذف حساباته أو بياناته.
- إعادة إصدار كود التسجيل للمحل الجديد إذا فُقد الكود قبل استخدامه.
- سجل عمليات لإنشاء المحلات، استخدام الأكواد، التجديد، والإيقاف.
- حظر الدخول والطلبات المحمية آلياً عندما ينتهي الاشتراك أو يتم إيقاف المحل. لا تُحذف بيانات المحل عند انتهاء الاشتراك.

## توافق البيانات الحالية

أُضيف إلى `Store` الحقل `subscriptionRequired` بقيمة افتراضية `false`. لذلك تبقى المحلات والحسابات الموجودة قبل هذه الإضافة قادرة على العمل كما كانت ولا تُطلب منها اشتراكات بأثر رجعي. المحلات الجديدة التي تُنشأ من لوحة NEXOR تُسجل مع `subscriptionRequired = true` وتخضع للتحقق من الاشتراك.

لم تُحذف أي جداول أو حقول أو بيانات موجودة في المخطط المرسل. أُضيفت Migration جديدة فقط:

`backend/prisma/migrations/20261111190000_add_platform_subscriptions/migration.sql`

## تثبيت التحديث على Windows

1. خذ نسخة احتياطية من المشروع وقاعدة البيانات أولاً.
2. فك ضغط محتويات ZIP فوق مجلد المشروع `C:\nexor_orders` مع الحفاظ على المسارات.
3. افتح PowerShell:

```powershell
cd C:\nexor_orders\backend
npm run db:migrate
npm run db:generate
npm run build
```

4. أنشئ حساب مدير NEXOR الأول:

```powershell
npm run platform:admin:create
```

أدخل البريد الإلكتروني والاسم وكلمة مرور قوية لا تقل عن 12 محرفاً. لا يوجد حساب افتراضي أو كلمة مرور ثابتة داخل الكود. يمكن إعادة تشغيل الأمر لتحديث كلمة مرور مدير موجود بنفس البريد.

5. شغّل الخادم:

```powershell
npm run start:dev
```

6. في نافذة PowerShell ثانية:

```powershell
cd C:\nexor_orders
flutter pub get
dart format lib\main.dart lib\features\auth lib\features\platform_admin
flutter analyze
flutter run -d chrome
```

لا تحتاج الحزمة إلى إضافة Flutter dependency جديدة؛ تستخدم Dio وFlutter Secure Storage الموجودتين في `pubspec.yaml`.

## طريقة الاستخدام

### أ. دخول المالك

من شاشة تسجيل الدخول الرئيسية اضغط «دخول إدارة NEXOR»، ثم أدخل بيانات الحساب الذي أنشأته بالأمر `npm run platform:admin:create`.

### ب. إنشاء محل وإصدار كود

اضغط «إضافة محل»، أدخل اسم المحل وبيانات التواصل، وحدد مدة الاشتراك والمبلغ والعملة. سيُنشئ النظام المحل والاشتراك المعلّق وكود التفعيل في عملية قاعدة بيانات واحدة. انسخ الكود الذي يظهر وأرسله لصاحب المحل؛ لن يمكن استرجاع الكود كاملاً من شاشة المحلات لاحقاً لأنه مخزّن كـ Hash.

### ج. إنشاء حساب صاحب المحل

من شاشة التسجيل العادية اختر «أنشئ حساباً»، ثم أدخل الاسم الكامل وكود التفعيل والبريد الإلكتروني وكلمة المرور. سيحدد النظام المحل من الكود، وينشئ عضوية `OWNER` ويربط المستخدم بالمحل نفسه، ثم يبدأ مدة الاشتراك في لحظة التفعيل.

### د. انتهاء وتجديد الاشتراك

كل طلب محمي من حساب المحل يتحقق من وجود اشتراك فعال في الوقت الحالي. بعد `endsAt` يُمنع تسجيل الدخول والطلبات المحمية، وتبقى البيانات كما هي. يستطيع مالك NEXOR تجديد الاشتراك من لوحة المالك. إذا جُدد قبل الانتهاء، يبدأ التجديد بعد نهاية الفترة الحالية؛ وإذا جُدد بعد الانتهاء، يبدأ من لحظة التجديد.

## نقاط أمان مهمة

- لا تنشئ حساب Platform Admin عبر واجهة عامة؛ أنشئه من داخل مجلد Backend عبر الأمر المحلي.
- لا ترسل كلمات مرور المدير أو JWT أو `DATABASE_URL` لأي شخص.
- كود التفعيل مرتبط بـ `storeId` محدد، لا يمكن استخدامه لمحل آخر، ولا يمكن استخدامه مرتين.
- التحقق من الاشتراك يجري في Backend داخل JWT Guard، وليس بإخفاء زر أو صفحة في Flutter فقط.
- حسابات المحلات القديمة لا تخضع للاشتراك تلقائياً بسبب قيمة `subscriptionRequired = false` الافتراضية. تظهر في لوحة المالك بحالة «حساب قديم - بلا اشتراك». من زر «إدخال بنظام الاشتراك» يمكنك اختيار باقة وتاريخ تفعيلها؛ ينشأ اشتراك فعال من لحظة الإجراء وتبقى العضويات والبيانات القديمة كما هي. يشترط وجود عضوية `OWNER` في المؤسسة.

## حدود هذه المرحلة

- لا توجد حالياً صفحة تجديد ذاتي لصاحب المحل؛ التجديد يديره مالك NEXOR من لوحة المالك.
- لا يوجد إرسال تلقائي لرسائل التنبيه بعد 7 أو 3 أيام؛ اللوحة تعرض عدد الاشتراكات التي تنتهي خلال 7 أيام، ويمكن إضافة جدولة وتنبيهات لاحقاً.
- أول مالك للمحل ينشأ بكود التفعيل. إدارة حسابات الموظفين الحاليّة تبقى حسب آلية صلاحيات المستخدمين الموجودة في المشروع.
- لم يُنفّذ `npm run build` أو `prisma migrate` أو `flutter analyze` على جهاز المستخدم؛ يجب تشغيل أوامر التحقق بعد تركيب التحديث في بيئة المشروع الفعلية.
